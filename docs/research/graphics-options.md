The machine-readable catalog is `tools/data/graphics-options.json`, generated by
`python tools/extract_graphics_options.py` from the options file. Use `--check` to
compare it against an installed game. `tests/test_graphics_options.py` validates it.

## Where the settings live

- **Active settings:** `Documents\My Games\DiRT3\hardwaresettings\hardware_settings_config.xml`.
  This is the file the launcher already edits for desktop resolution, display mode and VSync
  (`DesktopGraphics.vb`) and for VR sessions (`ExperimentalFiles.vb`).
- **Options and presets:** `system/hardware_settings_options.xml`. Each `category` has `option`s,
  and each option lists the attributes it writes. The `graphicsDetail` category holds the five
  presets as `ref`s to the other categories.
- **Limits:** `system/hardware_settings_restrictions.xml` clamps or replaces values. See below.
- **Automatic detection:** `system/hardware_settings_ratings.xml` rates memory, CPU and GPU from 1 to 3
  (`totalMemory`, core count and hyper-threading, GPU device ID or name). The rating-to-preset mapping
  is not in these files; presumably it's in the executable. Not verified.
- `hardwaresettings/hardware_settings_config.xml` in the game folder (deviceId `0x6720`, Radeon HD 6970M,
  811×604) and `system/hardware_settings_config.xml` (template, `aspect="normal"`) are not the user's settings.
  The Documents copy has the current machine's deviceId (`0x2702`) and is the one the game rewrites.

The game's options menu shows these entries (`pc_gfx_*` strings in `dirt3_game.exe`): overall,
resolution, refresh, aspect, vsync, multisample, gamma, shadows, particles, mirrors, crowd, cloth,
dao (ambient occlusion), ground_cover, trees, objects, car_reflection, water, postprocess,
skidmarks, vehicles, headlights, and the stereo on/off, separation and viewplane settings. Physics (damage) has
no menu entry; only the presets and safe mode set it. `pc_gfx_headlights` presumably maps to
the `night_lighting` category (the options file has no `headlights` category). Not verified in the menu.

## DirectX 11 variants

A preset `ref` can carry `dx_11_option`, used instead of `option` under DirectX 11. Options marked
`dx11Only="true"` exist only under DirectX 11. DiRT3VR's VR session forces `forcedx9="false"`, and
the user's file has it too, so the catalog uses the DirectX 11 values and lists DirectX 9 differences
per preset (`dx9Differences`).

| Category | dx11Only choice |
|---|---|
| Shadows | ultra |
| Crowd | ultra |
| Cloth | low |
| Post-processing | high |

Ultra under DirectX 9 also uses Shadows high and Crowd high. Each preset also writes
`graphics_detail level="<preset>"`, a 1024×768 or lower 60 Hz resolution, fullscreen, auto aspect and VSync off.
A launcher preset should not copy those display values, because desktop and VR display settings are managed separately.

`graphics_detail@level` is only a label. The user's current file says `level="medium"`
while every quality value matches Ultra. Don't use it to detect the active preset; compare the values instead.

## Settings outside the presets

- **Multisampling** (`graphics_card/resolution@multisampling`): `off`, `2xmsaa`, `4xmsaa`, `8xmsaa`,
  `16xmsaa`, `8xcsaa`, `16xcsaa`, `8xqcsaa`, `16xqcsaa`, and the vendor-neutral levels `1`–`8`.
  `hardware_settings_info.xml` lists what the GPU supports (here off/2x/4x/8x). VR sessions force `off`
  (`ExperimentalFiles.vb`). VR anti-aliasing (#c8076a1e) needs renderer work.
- **Gamma** (`graphics_card/gamma@level`): 0.5–2.5 in 0.1 steps.
- **Aspect**: auto, 4:3, 5:4, 16:9, 16:10, 5:3.
- **Physics** (`physics@environmentalDamage`, `@vehicleDamage`): low false/false, medium false/true,
  high true/true. This is a gameplay setting, not graphics quality.
- **Stereo** (`graphics_card/stereo@enabled`, `separation` 0.005–0.1, `convergence` 0.5–6.0): the game's
  own 3D Vision-style stereo. DiRT3VR forces it off.
- **Safe mode** (`safe_mode` category): an 800×600 fullscreen, VSync-on, nearly-everything-off profile.

## Restrictions

`hardware_settings_restrictions.xml` (original) enforces the following. Where a "default" is given,
the game presumably substitutes it for out-of-range values. This is unverified.

| Element | Rule |
|---|---|
| `cpu/threadStrategy` | Replaced by core count (2, 3, 4, 6, ≥8, hyper-threading, else). All six branches originally set `parallelUpdateRender="true"`; DiRT3VR VR sessions temporarily change them to `false`. |
| `audio@mixing` | software, hardware, rapture3D (default rapture3D) |
| `resolution` | width ≤ 639 or height ≤ 479 → 640×480; aspect auto, 4:3, 5:4, 16:9, 16:10, 5:3 |
| `gamma@level` | 0.5–2.5, default 1.0 |
| `textures@lod` | integer ≥ 0, default 0 (no options entry; not in the config file) |
| `shadows@size` | 128, 256, 512, 768, 1024, 1536, 2048, 4096 (default 1024) |
| `shadows@maskQuality` | 0–2, default 1 |
| `headlights@headlightQuality` | 0–2, default 1 (no options entry; not in the config file) |
| `crowd@enabled`, `cloth@enabled` | bool, default true |
| `physics@environmentalDamage`, `@vehicleDamage` | bool, default true |
| `vehicles@characterQuality` | 0–4, default 2 (options use 0–2) |
| `water@detail` | 0–2, default 1 |
| `input@device_type` | auto, pad, wheel |

### Values beyond the menu (untested)

The restrictions allow values no preset uses. They could be candidates for VR-specific options, but
none has been tried in the game:

- `shadows@size="4096"` (Ultra uses 2048)
- `vehicles@characterQuality` 3–4
- `graphics_card/textures@lod` (presumably a texture mip bias, where higher values mean lower resolution; a Potato-preset candidate, #8df24f27)
- `headlights@headlightQuality` 0–2

## Not available as game settings

DiRT 3 has **no anisotropic filtering and no bloom setting**. There is nothing in the options,
restrictions or config files, and no `pc_gfx_*` menu string. `dirt3_game.exe` contains bloom shader
names (`bloomPrevalence`, `bloom.combine2`), so bloom is part of post-processing.
#15714dd2 (anisotropic filtering) therefore needs renderer (proxy) work, a sampler-state
override (`src/anisotropic_filter.cpp`); it cannot be done by writing the XML. #3c6d6ffa (bloom
on/off) turned out to be data after all: the post-processing effect files carry the bloom mixes
([bloom](bloom.md)).

In the game (2026-11-03, `run_benchmark.py --anisotropy 16`, Aspen): the log shows the level and
its first 16 changed samplers (it logs no more), all accepted by the driver. DiRT 3 already creates some samplers anisotropic
(4×, 6×, 8×) next to trilinear ones, so "Off" (1, trilinear) lowers those and 16× raises both.
At 1280×720 in the moving chase view the difference is small: far-road detail energy changed by
−2 to +2% in frames matched within 60 ms, inside the noise of motion blur and snow spray. A
slow or stationary view at a grazing angle, or the headset's higher resolution, should show
more; that's left to a visual check.

## Notes for the launcher graphics UI (#86b1ad13, #8df24f27)

- Write only the quality attributes from the catalog, into the Documents file, with the same
  atomic-write, backup and read-only handling as `DesktopGraphics.Apply`. Keep unrelated attributes
  and elements byte-for-byte where possible. The game itself rewrites the whole file on exit.
- "Use game setting" should remain the default for every control, as with the desktop display controls.
- The VR session applies its own temporary graphics changes on top of the file (`ExperimentalFiles.vb`)
  and restores the original afterwards. Quality choices for VR need to be merged into that transaction
  rather than written separately.
- Re-applying on every launch (#86b1ad13) is needed because the game rewrites the file. Whether
  the game also resets quality values when the deviceId changes or a restriction fails is unverified.
